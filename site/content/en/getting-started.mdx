# Getting started

Conclave runs on **Claude Code or Cursor** against the same `conclave/` directory.

- **Cursor and never installed Conclave?** Follow [Cursor from scratch](/en/installation#cursor-from-scratch) first (clone the plugin → install → then bootstrap **your app**).
- **Already on Conclave v1.x?** Run `/conclave-init --upgrade` — see [Upgrading from v1](/en/upgrade).
- Otherwise install your runtime via [Installation](/en/installation) / [Platforms](/en/platforms), then:

## Two commands to get going

Inside any git repo:

```bash
# 0. Optional, greenfield: write the product documentation package (docs/product/).
#    Skip it and /conclave-init offers it when it finds no product document.
/conclave-discovery

# 1. Once per repo: setup + inception.
#    Detects the stack, asks for project name, story prefix, language, launch date,
#    team profile and sprint length, then turns your idea (or product doc) into a
#    vision, epics, architecture and a sprint-by-sprint roadmap.
/conclave-init

# 2. Plan the first roadmap slot (Sprint 0 walking skeleton on a new repo).
/conclave-planning
```

After step 2 the sprint is `active`, every story has an assignee and a discipline, and the team can open a PR with the entire `conclave/` directory.

`/conclave-init` does not need a finished product document. It scans the repo for one, scores what it finds on five coverage signals (problem, users, goal/metrics, features/scope, MVP boundary), and when nothing usable exists offers [`/conclave-discovery`](/en/commands/discovery) — a guided pass that writes discovery, tech stack, data model, domain rules (BLOC) and MVP to `docs/product/`. A one-paragraph idea still works too, for a thinner inception. The Product Manager writes the vision (with the **Product Goal**) and 3–8 epics, the Tech Lead writes the architecture and ADRs, and the Scrum Master sequences the epics into roadmap slots. You confirm a one-screen summary before anything is written.

`/conclave-planning` then refines only the epics of the next slot into stories with Gherkin acceptance criteria, sizes the commitment against velocity, assigns by discipline, and locks the sprint.

## The sprint cycle

```
[/conclave-discovery] → /conclave-init (once) → /conclave-planning → /conclave-dev → /conclave-qa → /conclave-pr-review → /conclave-close → /conclave-planning → …
```

```bash
# Each dev picks up an assigned story
/conclave-dev US-001

# QA verifies the story when it reaches review
/conclave-qa US-001

# Tech Lead approves the PR (only when peer_pr_review.required is on)
/conclave-pr-review US-001

# At sprint end: review, optional retro, velocity, roadmap re-plan, reports
/conclave-close

# Next slot
/conclave-planning
```

`/conclave-dev --loop` drives Dev → QA → Tech Lead over the whole sprint unattended and leaves approved PRs for a human to merge. `/conclave-sprint` runs the build phase in one pass. Neither closes the sprint — only `/conclave-close` does.

## Sprint 0

On a repo with no application code, `sprint.sprint_zero` defaults to `true` and the roadmap starts with `SPRINT-000`: a **walking skeleton** made of `type: enabler` stories — scaffold for the confirmed stack, test framework with one passing test, lint, a CI workflow running both, and the `develop` integration branch. It gives `/conclave-dev --loop` something to run tests against from Sprint 1 on.

## What gets created

```
conclave/
├── README.md
├── config.md                         # project, stack, profile, sprint cadence
├── team/
│   ├── roster.md                     # who covers which discipline, plus optional PM/SM
│   └── ceremonies.md
├── product/
│   ├── vision.md                     # Product Goal, personas, success metrics
│   ├── roadmap.md                    # slots, burnup, forecast
│   ├── epics/EP-NNN-<slug>.md
│   ├── backlog.md                    # stories as they are refined
│   ├── architecture.md
│   ├── adr/ADR-NNN-<slug>.md
│   ├── definition-of-ready.md
│   └── definition-of-done.md
├── context/                          # frozen snapshots of inputs used
└── sprints/
    └── SPRINT-000/
        ├── meta.md                   # status, slot, epics, velocity
        ├── spec.md                   # sprint plan
        ├── planning.md               # planning record
        ├── stories/                  # PREFIX-001-slug.md
        ├── acceptance/               # AC-PREFIX-001.md
        ├── review.md                 # written by /conclave-close
        └── retro.md                  # written by /conclave-close when retro is on
```

Every file is markdown. Every change is a normal git diff your team can review in a PR.
