# /conclave-sprint

Drive the **build phase** of a sprint in a single invocation: plan the next roadmap slot if no sprint is active, then one pass of Dev → QA → PR review.

```
/conclave-sprint
/conclave-sprint --no-interaction
/conclave-sprint --headless
```

Closing the sprint — review, retro, velocity, reports — is [`/conclave-close`](/en/commands/close). This command never sets a sprint `closed` and never writes `conclave/report/`.

## Phases

| Phase | What it does | When it runs |
|---|---|---|
| **Phase 1 — Planning** | Runs [`/conclave-planning`](/en/commands/planning) inline for the next roadmap slot (refinement, TL feasibility, SM planning, validation, lock) | Skipped if a sprint is already `active` |
| **Phase 2 — Dev** | Dispatches all `ready` stories to the Developer/Designer/DevOps subagent (batch-of-3) | Skipped if no `ready` stories |
| **Phase 3 — QA** | Dispatches all `review` stories to the QA subagent (batch-of-3) | Skipped if no `review` stories |
| **Phase 4 — PR Review** | Dispatches all `verified` stories to the Tech Lead subagent (batch-of-3) | Skipped when `ceremonies.peer_pr_review.required: false` or no `verified` stories |

A workspace without `product/roadmap.md` (pre-v2) is refused with *"Run `/conclave-init --upgrade` first."*

## Phase output

Each phase prints a header and, after its batches, a summary table (same format as `/conclave-dev` and `/conclave-qa`):

```
## Phase 2 — Dev (4 stories)

| Story  | Branch               | PR                           | Outcome              |
|--------|----------------------|------------------------------|----------------------|
| US-001 | feat/US-001-login    | https://github.com/…/pull/42 | ✓ done               |
| US-003 | feat/US-003-settings | —                            | ✗ failed: <error>    |
```

Skipped phases always print a one-line notice:

```
Phase 4 — PR Review: skipped (peer_pr_review.required: false)
```

## Final summary and close hint

```
| Story  | Starting status | Final status | Notes               |
|--------|-----------------|--------------|---------------------|
| US-001 | ready           | done         |                     |
| US-002 | ready           | review       | ✗ QA: blocked       |
| US-003 | review          | done         | (was already review)|
```

When stories are still in flight, it points to `/conclave-dev --loop`. When every non-retired story is `done`, it prints:

```
All stories in SPRINT-NNN are done. Run /conclave-close to review the Increment,
run the retro, record velocity, and generate the sprint report.
```

## Model configuration

Reads the `models:` block from `conclave/config.md` and prints a one-line summary before Phase 1. Phase 2 routes by discipline (`design` → designer, `devops` → devops, everything else → developer). See the [configuration reference](/en/configuration#model-configuration-block-optional-v070).

## Failure behaviour

- **Phase 1 failure**: hard stop — `Sprint run aborted: Phase 1 (Planning) failed.`
- **Phase 2–4 per-story failure**: reported in the summary; other stories continue. A failed dev story stays `ready`.
- **QA `verdict: blocked`**: a normal outcome. The story stays `review`.

## Re-runs

Safe. Story `status` frontmatter is the recovery mechanism: Phase 2 collects `ready`, Phase 3 `review`, Phase 4 `verified`. Bugs (`BUG-NNN`) are never collected — fix them with `/conclave-dev BUG-NNN`.

## Headless one-pass

`--no-interaction` / `--headless`, or `commands.sprint.interactive: false`. The **same** single pass with prompts replaced by documented defaults:

- Planning (no active sprint): start today, end after `sprint.length_weeks` (default 2) weeks, first roster member as facilitator, Tech Lead as coverage-gap fallback. DoR failures drop back to `backlog`; over-capacity drops the lowest priority; under-capacity pulls nothing more.
- Phases 2–4 run unchanged. Phase 4 still honors `ceremonies.peer_pr_review.required` — headless does not force the TL gate.
- Nothing is merged, no run report is written, nothing is retried.

> **Changed in 0.15.0.** `commands.sprint.schedule` / `budgets` / `merge_method` are ignored no-ops and `--ignore-schedule` has no effect here. Unattended delivery is [`/conclave-dev --loop`](/en/commands/dev#autonomous-three-wave-delivery-loop-v0150).
>
> **Changed in 2.0.0.** The critical-bug gate, the closing reports and setting the sprint closed moved to [`/conclave-close`](/en/commands/close). Phase 1 now plans the next roadmap slot instead of locking a pre-existing `draft` sprint.

## Guardrails

- Phase 1 failure is a hard stop; all other failures are isolated per story.
- **Never merges a PR**, in either mode (ADR-006).
- Not a delivery loop: no self-heal, schedule, budgets, run report or token ledger.
- Never collects `BUG-NNN`.
- Writes only inside `conclave/`, plus story feature branches and the `tests/uat/` paths QA may write.
- Never closes a sprint.
