# /conclave-spec &lt;idea&gt;

Produce the **founding Scrum artifacts** for the current repo, from a one-line product idea plus all available project context. This is the MVP main command.

```
/conclave-spec "REST API for task management with JWT auth"
```

If `conclave/config.md` doesn't exist yet, this command runs the `/conclave-init` flow inline first rather than failing.

## What it does

1. Resolves the workspace and determines the next `SPRINT-NNN` ID.
2. Ingests project context in parallel: `CLAUDE.md` (project + global), the list of skills available in the session, and detected stack-signal files (`package.json`, `pubspec.yaml`, `go.mod`, etc.) — each snapshotted under `conclave/context/` for auditability.
3. **Detects an existing sprint plan document** (v0.16.0+) — scans the repo for any requirements or backlog document (`.md`, `.txt`, `.csv`, `.xlsx`, `.pdf`) using keyword matching (`user stor`, `backlog`, `sprint`, `acceptance criteria`, etc.). Two outcomes:
   - **Document found**: reads it and carries it as `EXISTING_PLAN`. Both the TL and PM agents receive it as source-of-truth context — stories derive from it first before the agents supplement.
   - **Nothing found**: pauses here and asks the user to share a document (markdown is strongly recommended to minimise token usage) or to continue without one.
4. Asks the user to confirm the detected stack, project type, how many stories to pull into Sprint 1 (3–5 default), and any hard constraints (deadlines, compliance, banned dependencies).
5. **Delegates to the Tech Lead and Product Manager in parallel** — two concurrent `Agent` calls, neither waits on the other:
   - **Tech Lead** produces the Architectural Foundation: overview, confirmed stack, component diagram, 3–7 ADRs, cross-cutting concerns, and a technical risk table.
   - **Product Manager** produces the Product Backlog as INVEST stories with MoSCoW priority, T-shirt estimates, and Gherkin acceptance criteria.
6. Synthesizes both outputs: writes `architecture.md`, builds the backlog table, picks the top N stories for Sprint 1, and splits each into a story file plus an acceptance file.
7. On re-runs, updates the backlog **additively** — never overwrites it.

## What it produces

- `conclave/product/backlog.md` — the ordered Product Backlog.
- `conclave/product/architecture.md` — the Architectural Foundation with ADRs.
- `conclave/sprints/SPRINT-NNN/` — the sprint draft: `meta.md`, `spec.md`, one `stories/US-NNN-<slug>.md` and one `acceptance/AC-US-NNN.md` per selected story.

Every story is created with `discipline: ""` (empty) — the Tech Lead assigns it later, during `/conclave-planning`, not here. See the [story state machine](/en/state-machine) for why.

All generated prose (story descriptions, acceptance criteria, architecture sections) is written in the `project_language` from `config.md` (default `es`).

## Existing plan document

If you already have a product roadmap, user stories, or a requirements document, share it when `/conclave-spec` asks. Supported formats:
- **Markdown** _(recommended)_ — lowest token cost, highest fidelity.
- Plain text (`.txt`) — good.
- CSV, PDF — readable but may need more tokens to interpret structure.

You can also paste the content directly in your reply when prompted. The PM and TL agents will derive stories from the document first, filling gaps only where the document is silent.

## Guardrails

- Does not modify any file outside `conclave/` (and only reads `CLAUDE.md`, never edits it).
- Does not commit — the team reviews the artifacts as a PR.
- The Product Backlog is append-only; per-sprint directories are always new, so they never collide.
- If the PM or TL output fails a quality check from its own role charter, the failure surfaces to the user with the specific check that failed — nothing is silently patched.

## After it runs

- [`/conclave-planning`](/en/commands/planning) locks the sprint and assigns each story's discipline and owner.
- [`/conclave-planning --all`](/en/commands/planning#multi-sprint-planning---all) plans every draft sprint in one pass.
