# /conclave-sprint

Maneja la **fase de build** de un sprint en una sola invocación: planifica el próximo slot del roadmap si no hay sprint activo, y después hace una pasada de Dev → QA → PR review.

```
/conclave-sprint
/conclave-sprint --no-interaction
/conclave-sprint --headless
```

Cerrar el sprint — review, retro, velocidad, reportes — es [`/conclave-close`](/es/commands/close). Este comando nunca pone un sprint en `closed` y nunca escribe en `conclave/report/`.

## Fases

| Fase | Qué hace | Cuándo corre |
|---|---|---|
| **Fase 1 — Planning** | Corre [`/conclave-planning`](/es/commands/planning) inline para el próximo slot del roadmap (refinamiento, factibilidad del TL, planning del SM, validación, bloqueo) | Se saltea si ya hay un sprint `active` |
| **Fase 2 — Dev** | Despacha todas las historias `ready` al subagente Developer/Designer/DevOps (lotes de 3) | Se saltea si no hay historias `ready` |
| **Fase 3 — QA** | Despacha todas las historias `review` al subagente de QA (lotes de 3) | Se saltea si no hay historias `review` |
| **Fase 4 — PR Review** | Despacha todas las historias `verified` al subagente Tech Lead (lotes de 3) | Se saltea cuando `ceremonies.peer_pr_review.required: false` o no hay historias `verified` |

Un workspace sin `product/roadmap.md` (pre-v2) se rechaza con *"Run `/conclave-init --upgrade` first."*

## Salida por fase

Cada fase imprime un encabezado y, después de sus lotes, una tabla resumen (mismo formato que `/conclave-dev` y `/conclave-qa`):

```
## Phase 2 — Dev (4 stories)

| Story  | Branch               | PR                           | Outcome              |
|--------|----------------------|------------------------------|----------------------|
| US-001 | feat/US-001-login    | https://github.com/…/pull/42 | ✓ done               |
| US-003 | feat/US-003-settings | —                            | ✗ failed: <error>    |
```

Las fases salteadas siempre imprimen un aviso de una línea:

```
Phase 4 — PR Review: skipped (peer_pr_review.required: false)
```

## Resumen final y aviso de cierre

```
| Story  | Starting status | Final status | Notes               |
|--------|-----------------|--------------|---------------------|
| US-001 | ready           | done         |                     |
| US-002 | ready           | review       | ✗ QA: blocked       |
| US-003 | review          | done         | (was already review)|
```

Si quedan historias en curso, sugiere `/conclave-dev --loop`. Cuando todas las historias no retiradas están `done`, imprime:

```
All stories in SPRINT-NNN are done. Run /conclave-close to review the Increment,
run the retro, record velocity, and generate the sprint report.
```

## Configuración de modelos

Lee el bloque `models:` de `conclave/config.md` e imprime un resumen de una línea antes de la Fase 1. La Fase 2 rutea por disciplina (`design` → designer, `devops` → devops, el resto → developer). Mirá la [referencia de configuración](/es/configuration).

## Comportamiento ante fallas

- **Falla en la Fase 1**: corte duro — `Sprint run aborted: Phase 1 (Planning) failed.`
- **Falla por historia en las Fases 2–4**: se reporta en el resumen; las demás historias siguen. Una historia que falla en dev queda `ready`.
- **QA `verdict: blocked`**: resultado normal. La historia queda en `review`.

## Re-ejecuciones

Son seguras. El frontmatter `status` de cada historia es el mecanismo de recuperación: la Fase 2 junta `ready`, la Fase 3 `review`, la Fase 4 `verified`. Los bugs (`BUG-NNN`) nunca se recolectan — arreglalos con `/conclave-dev BUG-NNN`.

## Headless de una pasada

`--no-interaction` / `--headless`, o `commands.sprint.interactive: false`. La **misma** pasada única con las preguntas reemplazadas por defaults documentados:

- Planning (sin sprint activo): arranca hoy, termina después de `sprint.length_weeks` (default 2) semanas, el primer miembro del roster como facilitador, el Tech Lead como fallback de huecos de cobertura. Las historias que fallan el DoR vuelven a `backlog`; sobre-capacidad saca la de menor prioridad; sub-capacidad no suma nada.
- Las Fases 2–4 corren igual. La Fase 4 sigue respetando `ceremonies.peer_pr_review.required` — headless no fuerza el gate del TL.
- No se mergea nada, no se escribe run report, no se reintenta nada.

> **Cambió en 0.15.0.** `commands.sprint.schedule` / `budgets` / `merge_method` son no-ops ignorados y `--ignore-schedule` no tiene efecto acá. La entrega desatendida es [`/conclave-dev --loop`](/es/commands/dev).
>
> **Cambió en 2.0.0.** El gate de bugs críticos, los reportes de cierre y poner el sprint en closed pasaron a [`/conclave-close`](/es/commands/close). La Fase 1 ahora planifica el próximo slot del roadmap en vez de bloquear un sprint `draft` preexistente.

## Guardrails

- La falla en la Fase 1 es un corte duro; las demás fallas se aíslan por historia.
- **Nunca mergea un PR**, en ningún modo (ADR-006).
- No es un loop de entrega: sin self-heal, schedule, budgets, run report ni ledger de tokens.
- Nunca recolecta `BUG-NNN`.
- Solo escribe dentro de `conclave/`, más las ramas de feature de las historias y los paths `tests/uat/` que QA puede escribir.
- Nunca cierra un sprint.
